# Demonstration evidence

Generated by `python tools/render_evidence.py` from a real local run of the **unmodified pipeline code** against in-memory stand-ins for OTM, Object Storage, and Google Drive ([local_runner/fakes.py](../local_runner/fakes.py)). All POD files are synthetic images and PDFs created by the demo. No OTM, OCI, or Google account was used.

| File | Demonstrates |
| --- | --- |
| `01-unit-tests-passing.png` | 12 tests: TIFF/image conversion, PDF passthrough, rejection of non-POD files, resilient merge, per-customer grouping, validation reasons, Drive upload and link index, append vs. replace with stable links, no reprocessing, backlog continuation, run locking. |
| `02-run1-merge-and-validation.png` | Run 1: 8 PODs. 6 merged into 3 customer files with Drive links, 1 invoice out of scope, 1 text file rejected, 1 POD skipped on a 403. |
| `03-run2-append-and-replace.png` | Run 2, same day: Customer A's new POD appended (3 → 4 pages). Customer B's re-scanned POD replaces the old scan (4 → 5 pages). Drive links unchanged. |
| `04-object-storage-layout.png` | Objects written after both runs, plus the per-day link index. |
| `demo-output/` | The merged synthetic PDFs, both run summaries, the link index, and the object listing. |

Everything in this folder is synthetic. It must never contain real POD files, customer names or codes, OTM hosts, OCIDs, or credentials.
